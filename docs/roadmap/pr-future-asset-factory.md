# PR futuro — Asset Factory

## Objetivo

Documentar la futura Asset Factory de JARVIS: un sistema para crear, mejorar, medir y monetizar activos digitales.

JARVIS no debe limitarse a completar tareas.
Debe convertir oportunidades en activos reales que puedan generar ingresos, tráfico, leads, validación o aprendizaje útil.

La Asset Factory debe transformar:

idea → misión → activo → publicación aprobada → medición → mejora → monetización

## Qué es un activo

Un activo es cualquier pieza digital que pueda aportar valor repetido sin depender 100% del tiempo humano directo.

Ejemplos:

- web afiliada.
- landing page.
- microSaaS.
- calculadora online.
- comparador.
- newsletter.
- lead magnet.
- ebook.
- curso.
- directorio nicho.
- plugin.
- extensión.
- automatización B2B.
- dashboard.
- API pequeña.
- herramienta SEO.
- canal de YouTube.
- serie de Shorts.
- producto digital.
- plantilla.
- base de datos curada.
- sistema interno reutilizable.

## Principio central

JARVIS no debe crear por crear.

Cada activo debe tener:

- hipótesis.
- objetivo.
- público.
- canal de distribución.
- métrica de éxito.
- coste estimado.
- riesgo.
- plan de medición.
- condición de cierre.
- posible vía de monetización.

## Relación con Money Engine

Money Engine decide qué activos merecen prioridad.

Asset Factory construye, empaqueta y mejora esos activos.

Ejemplo:

Money Engine detecta:
"Calculadora online para estimar costes de reforma con afiliados."

Asset Factory crea:
- landing.
- calculadora.
- copy.
- SEO básico.
- tracking.
- CTA afiliado.
- checklist descargable.
- plan de mejora.

## Relación con Mission Control

Cada activo debe nacer como una Mission.

Ejemplo:

Mission:
"Crear MVP de web afiliada sobre herramientas IA para estudiantes."

Steps:
- investigar keywords.
- elegir propuesta.
- crear estructura.
- generar landing.
- crear contenido inicial.
- preparar tracking.
- revisar riesgos.
- pedir aprobación para publicar.
- medir resultados.

## Relación con Content / YouTube Factory

Content Factory crea piezas de contenido.

Asset Factory convierte esas piezas en activos persistentes.

Ejemplos:

- un vídeo se convierte en landing.
- un short se convierte en lead magnet.
- un guion se convierte en artículo.
- una serie se convierte en newsletter.
- una audiencia se convierte en producto.

## Approval Gate

Requieren aprobación explícita:

- publicar un activo.
- desplegar en producción.
- comprar dominio.
- usar credenciales.
- conectar cuenta externa.
- gastar dinero.
- lanzar campaña.
- borrar activo.
- cambiar marca pública.
- enviar emails reales.
- usar datos personales.
- compromisos contractuales.
- cambios irreversibles.

## Protocolo antes de publicar un activo

JARVIS debe mostrar:

- nombre del activo.
- tipo de activo.
- objetivo.
- público.
- URL o destino.
- coste.
- riesgo.
- monetización prevista.
- tracking configurado.
- assets incluidos.
- acción exacta.
- qué ocurrirá si David aprueba.

Ejemplo:

"Acción sensible: publicar activo digital.
Activo: Calculadora de costes de reforma.
Tipo: calculadora online + landing afiliada.
Destino: producción.
Coste asociado: 0 €.
Riesgo: bajo.
Monetización prevista: afiliación / leads.

¿Autorizas publicar este activo?"

## Regla de cierre

JARVIS debe recomendar cerrar activos cuando no haya señales suficientes.

Un activo puede cerrarse si:

- no genera tráfico.
- no convierte.
- consume demasiado mantenimiento.
- no tiene canal de distribución.
- tiene riesgo legal alto.
- tiene coste mayor que retorno.
- no supera su condición de éxito.
- distrae de activos mejores.

Cerrar no significa perder todo.
JARVIS debe intentar reutilizar:

- código.
- copy.
- diseño.
- datos.
- aprendizajes.
- contenido.
- componentes.

## Riesgos

- Crear demasiados activos.
- Dispersión.
- Falta de distribución.
- Métricas falsas.
- Costes ocultos.
- Dependencia de plataformas.
- Riesgo legal.
- Copyright.
- SEO débil.
- Monetización pobre.
- Abandono por falta de foco.
- Automatizar ideas sin demanda.

## Decisión

Asset Factory debe ser el sistema que convierte la inteligencia de JARVIS en activos reales.

Money Engine decide prioridad.
Mission Control ejecuta.
Asset Factory empaqueta y mejora.
Approval Gate protege las acciones sensibles.
David mantiene la decisión final.
